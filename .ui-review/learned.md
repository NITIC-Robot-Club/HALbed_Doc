# 持ち越し

## 以前のデザインへ戻すとき（2026-10-26）

- 復元基準のコミットと、利用者が残したいと指定した画面部分を先に分ける。今回はマージ前のmainを基準にし、トップのヒーローと開発資料の検索部は添付画像の状態を維持する。
- 一覧の配置を過去版へ戻しても、新しく追加された記事・計算ツールへの入口は残す。主要タグから同一ページの結果へ切り替えるときは、結果の見出しへフォーカスとスクロールを移す。

- 長いAPI宣言は横スクロールではなく表示幅に合わせて折り返す。関数名と構造体名を同じ署名バー内に残すと、関数と説明の対応を追いやすい（HAL API署名バー / 2026-10）。
- 署名に構造体型を追加するときは、リンク先ページの型見出しIDも確認する（HAL API署名バー / 2026-10）。

## 記事一覧の探索

- カテゴリ名だけを並べて別の検索画面へ送ると、記事の中身を判断する前に移動が必要になる。カテゴリと代表記事名を同時に表示し、同じ画面で検索・分野・タグを組み合わせる（開発資料トップ / 2026-10）。
- 一覧ページに本文用のタグ・関連記事を自動挿入すると、探索入口が重複する。一覧専用レイアウトを選び、実際のカタログに存在する分野だけを案内する（開発資料トップ / 2026-10）。
- 320pxのbody最小幅は、縦スクロールバーを含む320px viewportでは横スクロールを生む。画面の見た目だけでなくclientWidthとscrollWidthも比較する（開発資料トップ / 2026-10）。

## ツールの選択

- 似た計算ツールはカテゴリと短い名称で区別する。必要な差だけを名称に含め、全項目への用途説明・入出力欄の追加は避ける。対応範囲を左右するbxCANなどの条件は残す（計算ツール一覧 / 2026-10-26、説明過多の指摘を反映）。
- 固定ヘッダーの余白を戻す際は、モバイルでナビが通常フローに入る状態も確認する。PCで必要な余白を全幅に適用すると、モバイルでは余白が二重になる（計算ツール一覧 / 2026-10）。

## 線と枠を役割で選ぶ（2026-10-26）

- 枠は一律に禁止しない。トップのドキュメント入口は各項目全体が遷移操作であり、8px角丸の枠を使う。入力・選択欄は6px。本文のリンクと分野一覧へ同じ囲いを広げない。
- 計算の主結果と単位換算一覧で、同じ量・同じ単位を2回出さない。主結果を残し、重複する換算行を除く（トルクのN·m、出力のW）。
