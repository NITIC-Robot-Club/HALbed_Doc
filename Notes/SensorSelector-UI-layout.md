# センサー選定UIの固定高さレイアウト

## 目的

センサー選定の開始画面、分岐選択画面、全体図で表示高さを揃え、状態遷移時の画面の揺れを抑える。縦方向は選定キャンバスを主役にする。

## 対象範囲

- 実装: `.vitepress/theme/components/SensorSelector.vue`
- 全体図: `.vitepress/theme/components/SensorOverviewGraph.vue`
- 表示ページ: `Docs/Tools/SensorSelector.md`

## 判断基準

- 外枠の高さは状態によらず共通にする。
- 高さは `clamp(18rem, calc(100svh - 7rem), 42rem)` を使い、viewportに応じて変わるが、同一viewport内では状態遷移で変えない。
- 詳細画面は「選択経路・説明」「キャンバス」「結果」の3段にし、キャンバスを `minmax(0, 1fr)` で残り領域に広げる。
- 開始画面と全体図も同じワークスペース内でキャンバスを伸縮させる。
- 操作ボタンは自然幅・小さいgapで同じ列にまとめ、390px幅でも過剰な縦積みを避ける。

## 実施手順

1. `.sensor-selector__workspace` に共通の固定高さ、`box-sizing: border-box`、`overflow: hidden` を設定する。
2. 選定画面をflex/grid化し、キャンバスを可変の中央行へ配置する。
3. 全体図をflex化し、ツリー領域を残り高さへ伸ばす。
4. モバイルでは操作列をflexの自然幅ボタンにし、縦長のボタン格子を避ける。
5. 全体図はグラフの元の座標を変えず、表示領域の幅から一様倍率を計算して縮小する。倍率は読みやすさを優先して70%未満にしない。
6. 全体図のDOM生成とズームトランジションが完了してから選択ノードを再センタリングする。
7. 390px幅とデスクトップ幅でDOM寸法・画面遷移・スクロールを確認する。

## 検証方法

- `npm run docs:build` が成功すること。
- 1280x720相当ではワークスペース高さが608pxになること。
- 390x844では開始画面・詳細画面とも外枠高さが672pxになること。
- 390px幅の詳細画面で「戻る」「最初から」「全体表示」が1列に収まること。
- 詳細画面のキャンバスが約436px、全体図のツリー領域が約390px確保されること。
- 画面遷移後にページ全体のスクロール位置が不意に変わらないこと。

## 注意点

- `height` にpaddingを加算しないよう、固定高さを持つworkspaceは `border-box` にする。
- 開始画面は説明・結果が非表示になるため、gridの行定義を `minmax(0, 1fr)` へ上書きしないとキャンバスが上部の内容高さに縮む。
- 全体図のツリーは拡大縮小用の大きなpaddingを持つため、表示位置の確認はスクロール位置とノードのbounding boxを併せて行う。
- 開発サーバーはこの環境ではOneDrive配下のアクセス制限により、必要に応じて昇格実行が必要になる。
- 前後候補の絶対配置は、親の `min-height: 100%` だけでは親の高さが確定せず、現在ノードと重なることがある。トラックと現在列には `height: 100%` を明示し、モバイルでは現在列に固定の最小高さを与える。
- 全体図では選定結果パネルを表示せず、選択経路だけを全体図ヘッダーに残す。ツリー全体の視認性とキャンバスの高さを優先する。
- 全体図のグループ枠は子ノードを包むため矩形領域として重なりやすい。大きな枠を表示せず、小さな見出しバッジ・透明背景・`pointer-events: none` にして、ノードと配線を主役にする。
- 全画面表示へ切り替えるとviewportサイズが変わるため、`fullscreenchange` 後に `requestAnimationFrame` と遅延再計測を挟んで選択ノードを再センタリングする。切り替え前のscroll位置をそのまま使うと、選択ノードが左下に残りツリーが崩れて見える。
- 全体図の自動フィットは `viewport.clientWidth / graph.width` で一様倍率を決める。横方向だけを縮める実装にすると、配線と階層の対応が崩れる。
- 自動フィット直後はCSSの `zoom` トランジション中でbounding boxが変化するため、`nextTick` だけでセンタリングしない。約240ms後に再計測してからスクロール位置を確定する。
- 自動フィット対象のDOMがまだ存在しない場合は保留フラグを消さず、次の描画タイミングで再試行する。早くフラグを消すと初回全体図が空白表示になる。
- 全体図のズーム用コンテナにviewport依存の巨大なpaddingを置くと、ツリーの左右に空白が増えて構造が見えにくくなる。通常の固定余白にして、選択ノードのスクロールは実際のノード位置で調整する。
- 複数の親から同じ子へ接続するノードは、遠い列へ置くと配線が画面を横断する。共有結果は親列の近くに置き、同列の派生ノードは横方向へ逃がして中間ノードを縦に貫かない。
- グループ表現は大きな塗りつぶし矩形や枠線より、小さな見出しバッジにすると配線とノードの視認性を保ちやすい。
- 同じ親から複数の子へ伸びる配線は、子ごとに同じ縦線を重ねず、親から共有トランクを1本だけ伸ばして各子へ水平分岐する。矢印は子へ向かう分岐線だけに付ける。
- ツリーの縦位置は固定値を列ごとに手修正せず、葉から順にサブツリーの高さを確保し、配置済みブロックの下端に一定gapを足して次のブロックを置く。親ノードは子ノード範囲の中央に置くと、内部・外部・回路の塊が互いに重ならない。
- 全体図の配線は選定ツリーの `children` から一対一で生成せず、`SensorOverviewGraphEdge` の配列として独立管理する。一つの親から複数の子への分岐と、複数の入力から一つの共有ノードへの収束を同じモデルで表現する。
- 複合構成を別のまとまりとして見せる場合は、グラフノードに `layout: 'fixed'` を指定して自動フロー配置から除外し、外部ノードからの配線だけを残す。エンコーダーでは、回転数・相対／絶対角度・原点どりを同じパネル内に配置し、フォトインタラプタとリミットスイッチを原点どりへ収束させる。
- パネル型グループは `className: 'is-panel'` で明示し、ノードと配線を前面に残す。グループを通常の見出しバッジと同じ描画層に置くことで、枠が配線やクリック対象を奪わないようにする。
