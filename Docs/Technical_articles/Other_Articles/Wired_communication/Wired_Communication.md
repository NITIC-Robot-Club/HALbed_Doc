# 有線通信の基本

ロボットでは、センサーの値を読む、モータードライバへ指令を送る、別のマイコンと情報を共有する、といった場面で通信を使います。

通信方式は、機器の仕様で決まることが多いものです。自分で選べる場合は、通信距離、速度、配線、ノイズ、接続する機器の数を比べます。

## まずは比較する

| 方式 | 主な通信線 | 特徴 | よく使う場面 |
|---|---:|---|---|
| UART | TX、RX | シンプルな1対1通信 | PC、無線モジュール |
| I²C | SDA、SCL | 2本の線を複数機器で共有 | センサー、IC |
| SPI | SCK、MOSI、MISO、CS | 高速。機器ごとにCSが必要なことが多い | 表示器、高速センサー |
| CAN | CAN_H、CAN_L | 差動通信。複数ノードで共有 | モーター制御、車載機器 |
| S.BUS | 信号線1本 | RC機器の複数チャンネルをまとめて送る | プロポ受信機 |

表の本数は通信信号線の数です。電源やGND、シールド線は含めていません。SPIの`CS`は接続するターゲットごとに必要になる場合があります。

また、TTLは通信方式ではなく、UARTなどで使われる電圧レベルの一種です。UARTと書かれていても、5Vか3.3Vか、RS-232やRS-485のような別の電気規格かを確認してください。

## UART

UART（Universal Asynchronous Receiver Transmitter）は、クロック線を使わずに送受信する非同期シリアル通信です。送信側と受信側で、通信速度、データ長、パリティ、ストップビットを合わせます。

```text
機器A TX  ---->  機器B RX
機器A RX  <----  機器B TX
機器A GND --------  機器B GND
```

PCとのデバッグ通信、マイコン間通信、BluetoothやIM920などのモジュール接続でよく使います。配線と設定が簡単な一方、通常は1対1接続で、長距離や強いノイズには向きません。

代表的な通信速度には9600 baud、115200 baudなどがあります。速度を上げるほど、配線や信号品質の条件が厳しくなります。

## I²C

I²C（Inter-Integrated Circuit）は、SDA（データ）とSCL（クロック）の2本を複数の機器で共有する通信方式です。

```text
MCU ── SDA ─┬─ IMU
     └─ SCL ─┼─ 磁気エンコーダー
             └─ カラーセンサー
```

各ターゲットにはアドレスがあり、コントローラーがアドレスを指定して通信します。SDAとSCLはオープンドレインで動作するため、通常は両方にプルアップ抵抗が必要です。

複数のセンサーを少ない配線で接続できる反面、バス容量やプルアップ抵抗の影響を受けます。長い配線や強いノイズ環境には向きません。

| モード | 最大通信速度の目安 |
|---|---:|
| Standard-mode | 100 kbit/s |
| Fast-mode | 400 kbit/s |
| Fast-mode Plus | 1 Mbit/s |
| High-speed mode | 3.4 Mbit/s |
| Ultra Fast-mode | 5 Mbit/s |

実際に使える速度は、接続する機器、バス容量、プルアップ抵抗で決まります。[I²Cのプルアップ抵抗](./pullup-resistor)も参照してください。

## SPI

SPI（Serial Peripheral Interface）は、クロックを使って高速にデータを転送する方式です。主な信号は次の4つです。

- `SCK`：クロック
- `MOSI`：コントローラーからターゲットへのデータ
- `MISO`：ターゲットからコントローラーへのデータ
- `CS`：通信するターゲットの選択

```text
MCU SCK  ─────────┬─ Device A
MCU MOSI ─────────┼─ Device B
MCU MISO ─────────┤
MCU CS_A ─────────┘
MCU CS_B ─────────── Device B
```

UARTやI²Cより高速にしやすく、表示器や高速センサーで使われます。一方、ターゲットが増えるとCS線も増える構成が一般的です。通信モード（CPOL / CPHA）も相手機器と合わせます。

## CAN

CAN（Controller Area Network）は、複数のノードがCAN_HとCAN_Lの2本のバスを共有する通信方式です。差動信号を使うためノイズに強く、送信するメッセージのIDで優先順位を決められます。

CAN対応マイコンでも、CAN_HとCAN_Lを直接駆動できるとは限りません。通常は、マイコン内のCANコントローラーと、電気信号を変換するCANトランシーバを組み合わせます。

```text
アプリケーション
        ↓
CANコントローラー
        ↓ TX / RX
CANトランシーバ
        ↓
CAN_H / CAN_L
```

CANの通信速度、ケーブル長、終端抵抗、支線長には関係があります。Classical CANでは1 Mbit/sが代表的な上限ですが、実際の上限は規格と配線条件で決まります。CAN FDではデータフェーズだけを高速化でき、目標速度はトランシーバと配線に合わせて決めます。

CANでは、バスの両端に通常120Ωの終端抵抗を1本ずつ置きます。電源を切ってCAN_HとCAN_Lの間を測ったとき、2本の終端が並列になって約60Ωになるのが目安です。

詳しい仕組みは、[CANコントローラーとトランシーバ](./01-controller-and-transceiver)や[CAN / CAN FD入門](./03-network-basics)から参照できます。

## S.BUS

S.BUSは、RCプロポの受信機から複数チャンネルの操作情報を送る通信形式です。1本の信号線で多くのチャンネルを扱えるため、マイコンで操縦入力を読むときに使われます。

代表的なS.BUSは、反転信号を使う100000 bps、8E2のUARTに似た形式です。受信機やS.BUS2で差がある場合があるため、接続する機器の資料を確認します。

反転をマイコンのUART設定で処理できない場合は、外部の反転回路が必要です。信号電圧も受信機とマイコンの仕様に合わせます。

## まとめ

通信方式は、機器の仕様と、必要な距離・速度・配線・ノイズ耐性で選びます。

- UART：簡単な1対1通信
- I²C：複数のセンサーを2本の線で接続
- SPI：短距離で高速に通信
- CAN：複数ノードで共有し、ノイズの多い環境で使う
- S.BUS：プロポの複数チャンネルを受信機から読む

方式の名前だけでなく、電圧レベル、GND、終端、プルアップ、通信設定まで相手側と合わせることが重要です。
