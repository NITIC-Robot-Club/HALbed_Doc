# CAN / CAN FD入門 第6編
## 回路設計から通信確認までの実践手順

CANが動かないとき、原因はソフトウェアとは限りません。

ビットレート、ピン設定、トランシーバ、終端抵抗、配線、GND、IDフィルター。どれか一つが違うだけで、同じ「受信できない」という結果になります。

切り分ける順番を決めておくと、確認は速くなります。

## 1. 要求を先に固定する

回路やコードを書く前に、少なくとも次を決めます。

- Classical CANかCAN FDか
- 標準IDか拡張IDか
- 公称ビットレート
- CAN FDでBRSを使うか
- データビットレート
- 最大バス長と支線長
- ノード数
- 絶縁の要否
- メッセージ周期と許容遅延

CAN FDという名前だけでは、通信条件は決まりません。公称ビットレートとデータビットレートの両方が必要です。

## 2. ハードウェア構成を確認する

基本経路は次のようになります。

`アプリケーション → CANコントローラ → CANトランシーバ → CAN_H / CAN_L`

![CANコントローラとトランシーバ](./images/Wired_Communication/can-controller-vs-transceiver.png)

確認項目は次のとおりです。

- マイコンのCAN TX/RXピンが正しい
- トランシーバのTXD/RXD方向が正しい
- Standby、Enable、Silent端子が動作状態になっている
- トランシーバの電源電圧とI/O電圧が適合している
- CAN FDでは目標データビットレート対応品を選んでいる
- 必要に応じてGNDまたは絶縁回路を接続している

トランシーバのStandby端子が固定されていないため、受信だけできない、送信だけできないという故障に見える場合があります。

## 3. 電源OFFで配線を確認する

最初に抵抗測定を行います。

CAN_HとCAN_L間が約60 Ωなら、120 Ωの終端が2本ある目安になります。約120 Ωなら片側不足、60 Ωより小さければ終端過多を疑います。

次に導通を確認します。

- CAN_Hが各ノードのCAN_Hへつながっている
- CAN_Lが各ノードのCAN_Lへつながっている
- CAN_HとCAN_Lが短絡していない
- GND基準が必要な範囲にある

電源OFFの確認だけでも、終端抵抗の不足や過多、CAN_H/CAN_Lの短絡などを除外できます。

## 4. まず2ノードで動かす

最初から多数のノードを接続すると、どのノードがエラーを出しているのか分かりにくくなります。

送信ノードと受信ノードの2台、短い幹線、正しい終端という最小構成から始めます。

送信側だけの1ノード構成ではACKが返らず、再送が続く場合があります。波形が出ていることと、送信が正常完了したことは別です。

## 5. コントローラ設定を合わせる

両ノードで次を一致させます。

- 公称ビットレート
- サンプルポイント
- SJWとタイムセグメント
- Classical CAN / CAN FD
- BRSの使用有無
- データビットレート
- 標準ID / 拡張IDの扱い

「500 kbit/s」とだけ設定しても、クロック源や分周値が間違っていれば実際のビット時間は一致しません。マイコンのCANカーネルクロックから再計算します。

## 6. フィルターを一度広げる

物理層とフレームが正常でも、受信フィルターがIDを拒否しているとソフトウェアには届きません。

立上げ初期は、可能なら全IDを受信する設定で確認します。受信できた後に、必要なIDだけへ絞ります。

フィルター問題と配線問題を同時に追わないためです。

## 7. ロジックだけでなくバスを見る

CAN TXピンだけを測定しても、トランシーバの先で何が起きているかは分かりません。

オシロスコープでは次を確認します。

- CAN_HとCAN_Lが両方変化している
- ドミナント時に差動電圧が生じている
- 反射や大きなリンギングがない
- ACK位置にドミナントがある
- CAN FDではBRS後にビット幅が短くなる

差動プローブがない場合は、CAN_HとCAN_LをそれぞれGND基準で測り、演算機能で差を表示する方法もあります。プローブのGND接続方法には十分注意します。

## 症状から原因を絞る

| 症状 | 最初に確認すること |
|---|---|
| 波形がまったく出ない | ピン設定、クロック、トランシーバEnable |
| TXは動くがCAN_H/Lが動かない | トランシーバ電源、Standby、配線 |
| 同じフレームを繰り返す | ACK、相手ノード、ビットレート、終端 |
| エラーカウンターが増える | ビットタイミング、ノイズ、反射、H/L逆接 |
| 一部のIDだけ受信できない | ID形式、フィルター設定 |
| Classical CANは動くがCAN FDで失敗 | FD対応、BRS設定、データビットレート、配線品質 |
| 長いデータだけ失敗する | CAN FDのDLC、バッファ長、CRC領域付近の波形 |

## 設計時に残しておく情報

通信が動いた後こそ、条件を記録します。

- CANクロック周波数
- ビットタイミング設定値
- 公称／データビットレート
- サンプルポイント
- 使用トランシーバ
- 終端抵抗の位置
- ケーブルと支線長
- ID一覧、周期、DLC、信号配置
- Bus Off復帰方法
- 自動再送の設定

この記録がなければ、基板やマイコンを変更したときに同じ切り分けを繰り返すことになります。

## シリーズのまとめ

CANを理解する順番は、配線からでもフレームからでも構いません。ただし最後には、次の関係がつながっている必要があります。

`差動信号 → ドミナント／レセシブ → ID調停 → フレーム → エラー処理 → CAN FDの速度切替`

CANは「2本の線でデータを送る規格」ではありません。

複数ノードが同じバスを共有し、優先度を守り、異常なフレームを全体で排除するための仕組みです。その上に、CAN FDがデータ量と転送効率の拡張を加えています。
