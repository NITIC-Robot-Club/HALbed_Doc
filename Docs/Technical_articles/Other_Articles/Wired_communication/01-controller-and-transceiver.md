# CANコントローラとCANトランシーバの違い

CAN通信を始めたばかりのころは、「CAN対応マイコンなのに、なぜ別のICが必要なのだろう」と疑問に思うことがあります。

実は、CAN通信は役割が2つに分かれています。

![CANコントローラとトランシーバの構成](./images/Wired_Communication/can-controller-vs-transceiver.png)

## CANコントローラ

CANコントローラは、マイコン内部に搭載されている周辺回路です。

例えば STM32G4 や STM32F4 の FDCAN / CAN ペリフェラルがこれに当たります。

主な役割は次のとおりです。

- CANフレームの生成
- CANフレームの受信
- CRCの計算
- Arbitration（調停）
- ACKの送受信
- フィルタリング
- 送受信FIFOの管理

つまり、**CAN通信のルールを処理する部分**です。

ただし、この回路だけではCANバスへ直接接続できません。

## CANトランシーバ

CANトランシーバは、CANH・CANLへ接続するためのICです。

代表的な部品

- TJA1051
- SN65HVD230
- MCP2562
- TCANシリーズ

主な役割は、次のとおりです。

- MCUのTX/RX信号とCANH/CANLの変換
- 差動信号への変換
- バスの電気的な駆動
- ノイズ耐性の向上
- バス保護

つまり、**電気信号をCANバスへ流す役割**を担当しています。

## なぜトランシーバが必要なのか

マイコンのGPIOは通常、

- 0V
- 3.3V

のようなデジタル信号しか出力できません。

一方、CANバスでは

- CANH
- CANL

の2本を使った差動通信を行います。

マイコンのTX/RX信号と、CANH/CANLの差動信号を変換する回路が必要です。この変換をCANトランシーバが担当します。

## まとめ

| 部品 | 主な役割 |
|------|----------|
| CANコントローラ | CAN通信プロトコルを処理する（フレーム生成・CRC・調停など） |
| CANトランシーバ | TX/RXとCANH/CANLを変換し、CANバスを駆動する |

マイコンにCANコントローラが内蔵されていても、CANバスへ接続するには通常CANトランシーバが別途必要になります。
