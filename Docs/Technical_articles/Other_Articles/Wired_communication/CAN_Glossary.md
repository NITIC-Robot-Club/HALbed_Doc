# CAN 基本用語集

CANの説明では、通信線、メッセージ、フレーム、ID、ビットレートが一度に登場します。しかも、同じ「ID」でも送信先を示すとは限りません。最初は、CANを「複数のノードが2本のバスを共有し、ID付きのフレームを送る通信」と捉えると、用語同士の関係を追いやすくなります。

この用語集では、Classical CANを中心に、CAN FDで意味が変わる項目には注記を付けます。HALbedのAPIを読むときに必要になる `CANMessage`、フィルタ、FIFO、コールバックも最後にまとめています。

## まず押さえる全体像

```text
アプリケーションのデータ
        ↓
CANメッセージ
        ↓  ID、DLC、データを含む
CANフレーム
        ↓  調停、CRC、ACK、エラー処理
CANコントローラ
        ↓  TX / RX
CANトランシーバ
        ↓  差動信号
CAN_H / CAN_L
```

ここで、コントローラは通信の規則を処理し、トランシーバはマイコンの論理信号とバス上の電気信号を変換します。CAN対応マイコンでも、CAN_HとCAN_Lへ直接つなげるとは限りません。

## ネットワークと電気信号の用語

| 用語 | 英語と略称 | 基本的な意味 | 覚え方と注意点 |
|---|---|---|---|
| CAN | Controller Area Network | 複数の機器が同じ通信バスを共有する通信規格 | 送信先ではなく、メッセージの内容と優先度をIDで表す |
| ノード | node | CANバスに接続された機器。マイコン、ECU、センサー、アクチュエーターなど | 1台のノードが送信も受信もできる |
| バス | bus | 複数のノードが共有する通信線のまとまり | CANでは主にCAN_HとCAN_Lの2本を指す |
| CAN_H | CAN High | CANトランシーバが駆動する差動信号線の一方 | CAN_Lとの電圧差で信号を判定する |
| CAN_L | CAN Low | CANトランシーバが駆動する差動信号線のもう一方 | CAN_HとCAN_Lを入れ替えると通信できない |
| 差動信号 | differential signaling | 2本の信号線の電圧差で論理値を伝える方式 | 2本に共通して乗ったノイズの影響を受けにくい |
| CANコントローラ | CAN controller | ID、フレーム、調停、CRC、ACK、エラー処理を担当する回路 | マイコン内蔵のCAN周辺回路がこの役割を持つことがある |
| CANトランシーバ | CAN transceiver | コントローラのTX/RXとCAN_H/CAN_Lを電気的に変換するIC | バスへ接続するには通常トランシーバが必要 |
| 終端抵抗 | termination resistor | バスの両端に置く抵抗。一般的には120 Ωを1本ずつ使用する | 途中のノードには追加しない。電源オフ時のCAN_H-CAN_L間は約60 Ωが目安 |
| 幹線 | main bus | バスの両端を結ぶ主配線 | ノードの支線を長くしない |
| 支線 | stub | 幹線からノードへ分岐する短い配線 | 長すぎると反射や波形の乱れが起きやすい |
| メッセージ指向 | message oriented | 送信相手ではなく、情報の種類にIDを割り当てる考え方 | 1つのメッセージを複数ノードが利用できる |
| マルチマスター | multi-master | 固定された親機だけでなく、どのノードも送信を開始できる方式 | 同時送信時は調停で送信権を決める |

「2本だから何でも長距離で送れる」という意味ではありません。ビットレート、ケーブル長、終端、支線長、トランシーバの仕様は互いに関係します。

## フレームとメッセージの用語

メッセージは、アプリケーションが送りたい情報のまとまりです。フレームは、そのメッセージをCANの規則に従ってバスへ載せた通信単位です。日常の会話では混同されますが、データの意味と、通信上の形式を分けて考えると整理できます。

| 用語 | 英語と略称 | 基本的な意味 | 覚え方と注意点 |
|---|---|---|---|
| CANフレーム | CAN frame | SOF、ID、制御情報、データ、CRC、ACK、EOFなどを含む通信単位 | 「何を送るか」だけでなく「正しく届けるための情報」も含む |
| データフレーム | data frame | 実際のデータを運ぶフレーム | 通常、CANで送受信する中心的なフレーム |
| リモートフレーム | remote frame | 特定のIDのデータを送るよう要求するClassical CANのフレーム | CAN FDにはFD形式のリモートフレームはない |
| エラーフレーム | error frame | エラーを検出したノードが、現在のフレームを異常として知らせるフレーム | そのフレームは正常なデータとして扱われない |
| SOF | Start Of Frame | フレームの開始を示すビット | 各ノードがフレームの始まりを認識する |
| EOF | End Of Frame | フレームの終了を示す領域 | EOFの後に次の通信へ移る |
| ID | identifier | メッセージの種類を識別する番号 | 送信先アドレスではなく、調停時の優先度にも使われる |
| 標準ID | standard identifier | 11 bitのID形式 | Classical CANでは `0x000` から `0x7FF` |
| 拡張ID | extended identifier | 29 bitのID形式 | ID空間は広いが、フレームのID領域が長くなる |
| DLC | Data Length Code | データ長を表す制御情報 | Classical CANでは0～8 byte。CAN FDでは長さをコードで表す |
| データフィールド | data field | アプリケーションのデータを格納する領域 | Classical CANは最大8 byte、CAN FDは最大64 byte |
| CRC | Cyclic Redundancy Check | 受信したビット列の破損を検出するための検査値 | 形式の破損は検出するが、センサーの異常値までは検出しない |
| ACK | Acknowledge | フレームを正常に受信したノードが返す応答 | ACKがあっても、目的のアプリケーションがデータを使ったとは限らない |
| スタッフビット | stuff bit | 同じ論理値が5 bit続いたときに挿入される反対値のビット | 受信側が取り除く。データそのものではないが、通信時間には影響する |

IDが小さいフレームほど優先度が高いのは、IDのビット比較でドミナントが勝つためです。ただし「小さいIDほど通信速度が速い」という意味ではなく、同時送信時に送信権を得やすいという意味です。

## 調停とエラー処理の用語

CANは、複数ノードが同時に送信を始めても、優先度の高いフレームを壊さずに残します。この仕組みを理解すると、ID、ドミナント、レセシブ、エラーカウンターが一続きに見えてきます。

| 用語 | 英語と略称 | 基本的な意味 | 覚え方と注意点 |
|---|---|---|---|
| 調停 | arbitration | 同時に送信を始めたノードの中から、送信を続けるノードを決める処理 | IDを上位ビットから比較する |
| 非破壊調停 | non-destructive arbitration | 調停に負けたフレームだけが送信を止め、勝ったフレームは壊れずに続く仕組み | 「衝突したフレームを全部捨てる」方式ではない |
| ドミナント | dominant | バス上で優先される論理状態。一般に論理0に対応する | 1つでもドミナントが出ると、レセシブよりバスへ現れやすい |
| レセシブ | recessive | ドミナントに上書きされる論理状態。一般に論理1に対応する | 送信したレセシブとバス上のドミナントを比較して負けを検出する |
| Bit error | bit error | 送信した値と、読み戻したバスの値が一致しないエラー | 調停中など、正常動作として不一致が起きる場所は除く |
| Stuff error | stuff error | ビットスタッフィングの規則に違反したエラー | 同じ値が続きすぎた場合などに検出する |
| CRC error | CRC error | CRCの計算結果が一致しないエラー | 伝送途中のビット変化などを疑う手掛かりになる |
| Form error | form error | 固定形式のビットが規定値と異なるエラー | フレームの構造が崩れていることを示す |
| ACK error | ACK error | ACKスロットで受信ノードからドミナントが返らないエラー | 1台だけで送信した場合にも起きる |
| エラーカウンター | error counter | 送信エラーや受信エラーの蓄積を数えるカウンター | 値に応じてCANコントローラの状態が変わる |
| Error Active | error active | 通常の動作状態 | アクティブエラーフラグを送信できる |
| Error Passive | error passive | エラーが多く、バスへの影響を抑える状態 | 通信は続けられるが、エラー通知の影響が小さくなる |
| Bus Off | bus off | 重大な送信異常が続いたノードをバスから切り離す状態 | 復帰方法はコントローラとソフトウェアの設計で決める |
| 自動再送 | automatic retransmission | 送信に失敗したフレームをコントローラが再び送る機能 | ACK errorなどが続く場合、設定によってバスを占有し続けることがある |

エラーフレームが出たとき、原因は通信線だけとは限りません。ビットレートの不一致、CAN_H/CAN_Lの逆接続、終端抵抗、相手ノードの不在、Listen-only設定なども確認対象です。

## ビットタイミングと通信設定の用語

CANの「1 Mbps」は、単にソフトウェアで数字を設定すれば決まる値ではありません。CANコントローラのクロックを、1 bitを構成する時間単位へ分割し、各ノードが同じタイミングでサンプリングできるように設定します。

| 用語 | 英語と略称 | 基本的な意味 | 覚え方と注意点 |
|---|---|---|---|
| ビットレート | bit rate | 1秒あたりに送るビット数。単位は bit/s または kbit/s | CANでは相手ノードと一致させる |
| 公称ビットレート | nominal bit rate | 調停フェーズなどで使うCAN FDの基本ビットレート | Classical CANではフレーム全体の基本速度にあたる |
| データビットレート | data bit rate | CAN FDのデータフェーズで使う高速側のビットレート | 全ノード、トランシーバ、配線が対応している必要がある |
| ビットタイム | bit time | 1 bitを送る時間 | ビットレートの逆数。実際のフレーム時間はIDやスタッフビットでも変わる |
| タイムクォンタ | time quantum | ビットタイムを分割する最小の時間単位 | CANクロックと分周設定から決まる |
| サンプルポイント | sample point | 受信側がビット値を判定する時点 | 配線遅延やノイズの影響を受けるため、ビットレートと合わせて設定する |
| CAN FD | CAN with Flexible Data-Rate | データ長とデータフェーズの速度を拡張したCAN | 最大64 byte。Classical CAN専用ノードとの混在には注意が必要 |
| BRS | Bit Rate Switch | CAN FDでデータフェーズのビットレートを切り替える制御ビット | BRSを使わないCAN FDフレームもある |
| FDF | FD Format | Classical CANフレームかCAN FDフレームかを示す情報 | Classical CAN専用ノードがCAN FDフレームを解釈できるとは限らない |
| ESI | Error State Indicator | CAN FDフレームの送信ノードがError ActiveかError Passiveかを示す情報 | 受信ノードが送信側の状態を知る手掛かりになる |

通信速度を上げれば、常に通信が安定するわけではありません。速度が高いほど、ケーブル長、支線長、終端、サンプルポイント、トランシーバの余裕が厳しくなります。

## 受信処理とHALbed APIの用語

ハードウェアがフレームを受信しても、アプリケーションがすべてのフレームをそのまま使うとは限りません。受信フィルタで必要なIDだけを通し、FIFOへ蓄え、割り込みやコールバックでソフトウェアへ渡します。

| 用語 | 英語と略称 | HALbedでの意味 | 覚え方と注意点 |
|---|---|---|---|
| CANMessage | CAN message | Classic CANのID、データ、データ長などを保持する構造体 | `id`、`data`、`size`を使って送受信する |
| CANFDMessage | CAN FD message | CAN FDのID、最大64 byteのデータ、形式、BRSなどを保持する構造体 | `CANMessage`とは別の構造体として扱う |
| 受信フィルタ | acceptance filter | 受信するIDやID範囲をハードウェアで選別する仕組み | 不要なフレームをアプリケーションへ渡さない |
| フィルタID | filter ID | フィルタが比較の基準にするID | 受信したいIDや範囲に合わせて設定する |
| フィルタマスク | filter mask | IDのどのビットを比較するかを表す値 | マスクの設計を誤ると、受信漏れや不要な受信が起きる |
| FIFO | First In First Out | 受信したフレームを到着順に蓄えるキュー | FIFO 0とFIFO 1は別の受信経路として設定される |
| 受信割り込み | receive interrupt | FIFOへ新しいフレームが入ったことをCPUへ通知する仕組み | 割り込み内で長い処理やブロッキング処理をしない |
| コールバック | callback | 受信時にCANライブラリから呼び出される関数 | 受信データを短時間で退避し、重い処理は別の場所へ分ける |
| `attach()` | callback registration | HALbedの受信コールバックを登録するメソッド | `fifo`引数を有効化した受信FIFOと一致させる |
| `write()` | transmit | CANメッセージを送信キューへ追加するメソッド | 戻り値で送信要求が受け付けられたか確認する |
| `writeable()` | transmit availability | 送信キューへ追加できる空きがあるかを確認するメソッド | `true`でも、相手からACKを得られたことまでは示さない |
| Listen-only | listen-only mode | 送信やACKを行わず、バスを監視するモード | 解析には便利だが、相手ノードとしてACKは返さない |

HALbedでの具体的な設定は、[CAN API](../../../API/CAN)と[CAN FD API](../../../API/CANFD)を参照してください。フィルタの考え方は[CANフィルタの設定](../../MCU_Doc/CAN_Filters_Nbr)、再送の設定は[CANの自動再送](../../MCU_Doc/CAN_Retransmission)にまとまっています。

## よくある取り違え

### IDは送信先アドレスではない

ID `0x100`を送ったからといって、`0x100`という機器へ届くわけではありません。IDはメッセージの種類と優先度を表し、バス上の全ノードが受信できます。どのノードが使うかは、受信フィルタやアプリケーションが決めます。

### ACKはアプリケーションの応答ではない

ACKは、少なくとも一つのノードがフレームを通信上正しく受信したことを示します。データの意味を理解したこと、制御対象が動作したこと、目的のノードが処理したことまでは保証しません。必要なら、応答メッセージやタイムアウトを上位の通信仕様で定義します。

### CRCは値の正しさを保証しない

CRCが正常でも、センサーが故障して異常値を送った可能性は残ります。CRCは主に伝送中のビット破損を検出する仕組みで、範囲チェック、カウンター、タイムアウト、アプリケーション固有のチェックとは役割が異なります。

### CAN FDはデータを長くしただけではない

CAN FDでは、フレーム形式、データフェーズの速度切替、CRC、データ長コードなどが拡張されています。Classical CAN専用ノードが同じバスに接続されていても、CAN FDフレームを正常に扱えるとは限りません。
