# STM32 CAN の Auto Retransmission 設定に注意

STM32 の CAN / FDCAN では、`.ioc` ファイル作成時に **Auto Retransmission がデフォルトで Disable になっています**。(シリーズや、CubeMX / CubeIDE のバージョンによって異なる場合があります)

この設定が `Disable` のままだと、送信に失敗したメッセージが自動で再送されません。

## 調停に負けることはエラーではない

CANでは、IDの小さいフレームが高い優先度を持ちます。各ノードは送信しながらバスの状態を読み取り、自分がレセシブ（1）を送った位置でドミナント（0）を読むと、調停に負けたと判断します。

調停に負けたノードは、勝ったフレームを壊さないように送信を止めます。これは通信エラーではありません。自動再送が有効なら、バスが空いた後に送信を再試行します。

## Auto Retransmissionを無効にするとどうなるか

例えば、PCから複数の基板へ`ping`を送り、各基板が同時に`pong`を返すとします。

```text
基板1 → PC : pong, CAN ID = 0x101
基板2 → PC : pong, CAN ID = 0x102
基板3 → PC : pong, CAN ID = 0x103
```

この場合、`0x101`が調停に勝ちます。自動再送が有効なら、`0x102`と`0x103`も、`0x101`の送信後に順番に送られます。

自動再送を無効にしたFDCANでは、調停に負けた送信要求が自動的に再試行されないため、最初の調停で勝った`0x101`だけが送られたように見えることがあります。

同じ設定は、ACKが返らない場合や、送信中にエラーが発生した場合にも影響します。1台だけで送信テストをすると、ACKを返す相手がいないため、送信完了にならず再送を繰り返すことがあります。

## 確認する設定

CubeMX / CubeIDEの`.ioc`設定で、次の項目を確認します。

```text
Auto Retransmission = Enable
```

生成コードでは、FDCANは次の設定に対応します。

```c
hfdcan1.Init.AutoRetransmission = ENABLE;
```

通常のCANでは、次の設定です。

```c
hcan1.Init.AutoRetransmission = ENABLE;
```

シリーズやCubeMX / CubeIDEのバージョンによって初期値が異なる場合があるため、生成されたコードも確認します。

## 通常は有効にする

次のような通信では、自動再送を有効にする構成が扱いやすくなります。

- 応答確認
- 状態取得
- パラメータの読み書き
- 重要なイベント通知

ただし、自動再送を有効にしても、通信が必ず成功するわけではありません。タイムアウト、エラーカウンター、Bus Offなどをアプリケーション側でも監視します。

## 無効にする場合

周期的な制御指令では、古い指令を遅れて再送するより、次の周期の新しい指令を送る方がよい場合があります。そのような用途では、自動再送を無効にする設計も考えられます。

無効にする場合は、調停敗北や送信エラーで送れなかったフレームを、アプリケーション側で再送するのか、次の周期で上書きするのかを決めておきます。

## まとめ

- 調停敗北はCANの正常な動作であり、通信エラーとは異なる
- 自動再送が有効なら、調停に負けたフレームを後で再送できる
- 自動再送は、送信中のエラーやACK失敗にも関係する
- 通常の通信では`Auto Retransmission = Enable`を基本にする
- 無効にする場合は、送信失敗後の扱いを通信仕様へ書く
