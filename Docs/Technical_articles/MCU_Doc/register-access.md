# レジスタを叩くとは？

「レジスタを叩く」という表現は、マイコン開発でよく使われる俗語です。

少し乱暴な言い方ですが、「レジスタに直接値を書き込んでハードウェアを制御する」という意味で使われます。

例えばGPIOをONにしたい場合、HALライブラリを使うなら次のように書きます。

```c
HAL_GPIO_WritePin(GPIOA, GPIO_PIN_5, GPIO_PIN_SET);
```

一方で、レジスタを直接操作する場合はこのようになります。

```c
GPIOA->BSRR = GPIO_BSRR_BS5;
```

どちらもLEDを点灯させるという目的は同じですが、後者が「レジスタを叩いている」状態です。

## レジスタとは

レジスタは、マイコン内部にある設定用のメモリです。

GPIOやUART、タイマー、ADC、CANなどの周辺機能は、それぞれ複数のレジスタを持っています。

例えばGPIOには、

- 入力・出力を設定するレジスタ
- 出力をON/OFFするレジスタ
- 入力状態を読むレジスタ

などがあります。

マイコンは、これらのレジスタの値を見て動作しています。

## なぜ「叩く」と言うのか

レジスタへ値を書き込むことで、ハードウェアの状態がすぐに変化します。

そのため、

- レジスタを直接書き換える
- レジスタへ値を流し込む

という意味から、「レジスタを叩く」という表現が使われるようになりました。

正式な技術用語ではありませんが、多くの組み込み開発者が日常的に使っています。

## HALとの違い

STM32では、HALライブラリを使うことが多くあります。

HAL関数の内部では、最終的にはレジスタを書き換えています。

つまり、

HAL関数

→ HAL内部の処理

→ レジスタを書き換える

という流れになっています。

そのため、「HALを使う」と「レジスタを叩く」は対立するものではありません。

違いは、**自分で直接レジスタを書くか、HALに任せるか**です。

## レジスタを直接操作するメリット

- ハードウェアを細かく制御できる
- HALに用意されていない機能も使える
- 処理がシンプルになり、高速になる場合がある
- データシートやリファレンスマニュアルの理解が深まる

## デメリット

- 可読性が下がりやすい
- レジスタの意味を理解している必要がある
- マイコンが変わると移植しにくい
- 設定ミスによる不具合が起こりやすい

## どちらを使うべきか

通常のアプリケーションでは、HALやLLライブラリを使うことが多く、保守性も高くなります。

一方で、

- HALで対応できない設定
- 性能を限界まで引き出したい処理
- デバッグや原因調査

では、レジスタを直接操作することがあります。

実際の開発では、HALを基本とし、必要な部分だけレジスタを直接操作するという使い方がよく行われます。

## まとめ

「レジスタを叩く」とは、レジスタへ直接値を書き込み、ハードウェアを制御することを指す俗語です。

HALやLLライブラリも最終的にはレジスタを書き換えているため、違いは「誰がレジスタを書き換えるか」にあります。

組み込み開発では頻繁に耳にする表現なので、「レジスタを直接操作すること」と理解しておけば十分です。

マイコンの処理を高速化したい、もっと高度なピン操作をしたいとき、レジスタをぶっ叩きましょう。
